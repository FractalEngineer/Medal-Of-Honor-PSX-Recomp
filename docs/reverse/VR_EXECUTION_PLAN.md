# Stereo rendering execution plan

Date: 2026-10-02. Branch: `vr-dev` in the game and framework repositories.

The target is two genuine viewpoints of one guest scene state, with depth-dependent
parallax. The measured TRX injection at `FUN_8008B3E8` establishes level-geometry
parallax; it does not yet establish a complete replayable scene draw or stereo
presentation. Eye offsets of +/-24 remain uncalibrated.

## 1. Diagnose pass refusal

Keep the VSync(0) hook and no-op callback. Add failure-site instrumentation to
the framework and expose it through `render_pass_stats` over TCP, without printf
instrumentation. Preserve `refused` as the empty-plan counter and add separate
pass-attempt, begin-refusal and checkpoint-refusal counters.

Latch the last failure until session reset, including attempt/plan identifiers,
guest cycle, requested rect/alpha, status at rejection, actual capture dimensions,
scales, source path, active/open-generation state, generation validity/promotion,
resource stage, framebuffer status and stage-local GL errors. Distinguish errors
already pending before allocation from errors generated by the operation.

Instrument every pre-callback exit, including argument/status validation,
generation checks, backup allocation and checkpoint allocation/serialization.
Use existing `image_textures` only as supporting evidence that reservation was
reached; texture names do not prove valid storage.

Acceptance: a live TCP artifact identifies the rejecting branch and its inputs.
Do not infer the reason from a later status or sampled display dimensions.

## 2. Prove a no-op capture and restore

Fix the measured cause at its owner (the game hook or framework). Build with
`cmake --build build-debug --target psx-runtime`, using the updated pinned framework.
Launch windowed with `--no-launcher`, `PSX_VR_PROBE=1`, `PSX_VR_INTERP=1` and
`PSX_RENDER_PASS_VERIFY=1`. Headless cannot exercise the GL transaction.

Load gameplay slot 1 and arm `render_pass_dump` before attempts. Determine the
upcoming display rect from the game's DISPENV state rather than hook-count parity.
Ensure the plugin rejects recursive planning inside a pass. Retain the opt-in
probe controls while making attempts frequent enough for a bounded capture.

Acceptance: callback executes; a generation is promoted; baseline and no-op PNGs
exist and match; `verify_checks > 0`, `verify_mismatch = 0`. State-fingerprint
comparison and watchdog rollback must be checked before declaring redraw safe.
This milestone proves capture/restore, not stereo or redraw.

Measured update: the legacy VSync probe only attempted during startup in the
reproduction. Slot 1 uses `FUN_80090B80`'s DrawSync(-1) wait and an IRQ-driven
flip. The current no-op probe uses that main-thread function's entry, before
it enables the flip. It derives the upcoming DISPENV from the same buffer-index
calculation as the game. Enable `PSX_VR_PASS_PROBE=1`, `PSX_VR_INTERP=1` and
`PSX_RENDER_PASS_VERIFY=1`; leave `PSX_VR_PROBE=0` for TCP-only observation.

## 3. Identify the replayable draw slice

Trace the level scene driver through vertex transformation, primitive/ordering
table construction and GPU submission. Identify arguments and required renderer
state. Exclude logic advancement, input sampling, VSync, display flipping and
audio/CD side effects from the replayed draw slice.

Acceptance: redraw from one checkpoint produces the expected complete level
image, then dynamic objects and weapon coverage are verified independently.
Calling the vertex transformer alone does not satisfy this milestone.

## 4. Capture two eyes from the same checkpoint

Run each eye from the same CPU/GTE/RAM/device state. Apply TRX offset only while
that eye's draw runs; reset the host eye selector after the pass API returns,
including watchdog aborts. Verify offsets are not accumulated across transforms.

Acceptance: a pair of images carries one guest frame/cycle identifier, near
geometry separates more than far geometry, and the restored live timeline matches
a run without eye redraws. Record level, object, weapon and HUD coverage separately.

## 5. Separate stereo presentation from temporal interpolation

Factor the existing transaction/capture machinery for use by a paired-eye API.
Stereo must not depend on fictitious Q16 time phases or interpolation being on.
Retain applicable backend/session/watchdog protections. Publish both eyes
atomically under one frame identifier; if either fails, retain the preceding
complete pair. Budget and shed complete pairs, never individual eyes.

Start with a side-by-side presenter and per-eye dumps. Add headset submission
after paired capture, restoration and cost are measured. Calibrate eye separation,
projection/convergence and world scale after the paired-image proof.
